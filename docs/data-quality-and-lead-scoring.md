# 公式サイト品質・公開連絡先・物上げ適性スコア

## 目的

検索上位の第三者サイト、求人ページ、企業情報ディレクトリを公式サイトとして誤採用せず、公開された法人窓口だけを収集するための品質レイヤーです。

## 公式サイト判定

候補URLは次のシグナルを合算し、70点以上だけを採用します。

- 本文中の正規化会社名完全一致
- HTML titleの会社名一致
- JSON-LD構造化データの会社名一致
- 不動産事業表記
- 都道府県一致
- 会社概要・宅建免許表記
- 同一サイトの問い合わせ導線
- ルートページ

Wikipedia、求人媒体、不動産ポータル、電話帳、企業情報ディレクトリ、行政データベース等は拒否ドメインとして扱います。採用専用サブドメインも公式URL候補にしません。

## 公開メール

収集対象は `info@`、`contact@`、`sales@`、`support@` 等の公開された法人窓口です。個人名と推定されるローカルパート、no-reply、privacy窓口、公式サイトと無関係なドメインは除外します。小規模事業者が公開している汎用Gmail等は、法人窓口名の場合だけ許可します。

## 物上げ適性

次の公開表記を根拠として0〜100点で評価します。

- 直接買取・買取再販: 35点
- 用地仕入れ・開発: 25点
- 売主・オーナー向け導線: 15点
- 相続・空き家・任意売却: 15点
- 底地・借地・共有持分等: 10点
- 司法書士等との連携・業者向け窓口: 10点
- 問い合わせ導線: 5点

60点以上をA、35点以上をB、それ以外をCとします。スコアだけで断定せず、検出シグナルと根拠URLを保存します。

## 品質ゲート

```bash
python -m real_estate_db.quality_gate
```

既存データの問題は当初warningとしてレポートし、新しい確信度付きデータの問題はerrorとしてCIを停止します。既存行もすべてエラー扱いにする移行監査は次で実行します。

```bash
python -m real_estate_db.quality_gate --strict-legacy
```

レポートは `reports/data-quality.json` に保存されます。
